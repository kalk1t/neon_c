# Results publication/identity binding - 2026-11-04

Added rr_results_bind.{h,c}: a shared C adapter from the current full-pack UI frame/timer to frozen numeric and identity views. It uses the existing timer's snapshot/revision, captures local metadata only at a new final visible publication revision, and passes that immutable result/name view to a synchronous consumer. Names changing between finish and the two-second callback are captured at the callback boundary; names changing after publication do not rewrite an open result. Current profile is the eleven-racer local pack with player at roster 0. Metadata is supplied through a pure local name lookup because RRLocalRacer deliberately does not own account/identity strings.

Two caller-owned fixed name buffers permit atomic visible commit without a large stack object or heap allocation. Each name is copied immediately, so a lookup may reuse one transient return buffer. Borrowed views last until the next publication/reset and must not be retained as stack-view pointers. The verified font remains the row consumer's responsibility. At a single chosen UI boundary with several due callbacks, metadata remains stable and only the final published display is exposed; the source case with sixteen simultaneous publications validates this final-output equivalence, not side-effectful metadata getters or OS task priority.

Capture failure invalidates the new view and never pairs old names with new numbers. It is not retried on later frames of the same revision, because reading later metadata would violate the source publication boundary. A later new publication may capture again. Drawing failure preserves a valid frozen view for repaint, and lookup is not repeated. Status distinguishes identity, drawing, owner and core errors. Binding rejects another timer or a rewound publication revision. Timer and binding reset together only for a new application lifetime; race/menu hides retain queue/cache behavior. Completed simulation events must be submitted once even if view capture/drawing returns false, since the timer event may already have been consumed.

Native and WASM full suites each pass 120/120 CPU tests. Ten new actual-source virtual UI scenarios cover 51 boundaries and 24 source publications: before/at deadline, names changing every action, restart/pause/menu guards, old/new finish overlap, frozen repaint, equal-deadline FIFO, sixteen due callbacks, no duplicate publication and hide-with-finished-callback republishing. The chosen boundary explicitly orders finish schedule, hide, due pump and visible draw. Actual showResults display-prefix, fmt/esc/ordinal and Racer.progress are executed in an isolated virtual DOM, stopping before banking/account/unlocks/telemetry. Scripted actor progress/metadata remain explicit test inputs.

Those source scenarios produce 8 final publishing boundaries, 88 name lookups and 12 visible consumers; the consumer prepares/emits 264 rows and 4,962 recorded paint commands through the existing mixed-text renderer. It uses the retained source column tracks minus 26px list padding and the CSS-derived row stride, and reflows under the three supported glyph scales while preserving frozen names. It compares actual source DOM names/values, total text, display order and revisions. This supplied row-content geometry is not a whole-card/scroll/actual pixel test. Additional guard cases cover partial/absent/overlong lookup failures, no same-revision resampling, repaint/missing-consumer recovery, hidden cached data, alternate timer/rewind rejection and bad clocks.

The second new target routes the unchanged 1,440-tick source input/clock/player/full-pack oracle through this binding. It retains all actor/pose/event/shot/FX/coin/RNG checks and observes 42 result views with 33 name lookups across 3 publications. Frame-varying scripted names stay frozen at the publish frame; these names are fixture metadata, not real account identities. The reused browser-source hashes still match the current tree. No gameplay RNG is consumed by the adapter; the existing full replay remains 23,200 sequence draws and zero failures.

Resources: persistent binding 11328 bytes native/11300 WASM; borrowed view 120/60 bytes. String capacity is two sets of 11 names x 512 bytes, not a new nickname policy. No heap, new assets, GPU objects/uploads, font atlases or raised mesh/glyph limits. Per-row caller scratch is reused by the tests. All 455 source/copied assets match, v2 glyph provenance and the predecessor executable/source/test files remain unchanged except the intended CMake target update. The normal native main/solo UI is unchanged; production full-pack rivals/combat/coins and rewards remain inactive. The adapter is compiled and CPU-qualified, not wired into the real native full-pack renderer.
