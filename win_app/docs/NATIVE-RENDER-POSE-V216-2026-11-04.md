# Native body/pod pose conversion - 2026-11-04

Browser source/package remains v0.2.16. Normal solo rendering now takes the tracked RRCarPose explicitly, replacing its late scalar orientation recompute. The new rr_car_pose_raylib maps source column-major doubles into named raylib Matrix float fields; their in-memory struct order is not column-major and is never memcpy'd/transposed. Roadster body fit T(0,-0.35,0) is composed as a child of the source animated model group, after its hover/lift. No extra fit is applied to code-built fallback. Cached root keeps source timing after contact/damage/dodge instead of recomputing from newer numeric state.

Roadster vertices already contain GLB node placement. Each existing rr_pod_transform rotates around its baked pivot, then composes with the fitted parent for DrawMesh. Fallback's existing cubes use the source parent through rlMultMatrixf; fallback mesh shape and its pod geometry remain prototype. Existing scalar scene entry points are retained for compatibility; the normal player host calls the new explicit API. Invalid/unready/nonfinite/out-of-float-range transforms fail before draw submission, and main marks the offline session unavailable while completing the render frame normally. Body-hidden cockpit policy is unchanged.

New CPU-only source capture runs real Car.useModel/update/sync/place/idle/dodge and Three world matrices. It recreates original Roadster high-detail Object3D node names/pivots from the read-only GLB JSON, without loading mesh/texture data or creating a WebGL renderer. Source useModel performs its own -0.35 m child placement and pod binding. Across 1,440 frames, six speed/timing scenarios and source bank/spin/stun/contact/idle/placement history, actual Three supplies fitted body/fallback-parent points and four moving pod transforms. New capture root/car state is checked exactly against the earlier unchanged source oracle before header generation.

Fresh native and WASM builds each pass 108/108 CPU tests. The new raymath test checks 46,080 converted matrix values and 23,040 composed body/fallback/pod points (four body and four fallback-parent points, two points on each of four pods per frame), plus native/source pod angle history. Float32 comparisons use a 0.0005 m/component bound over these sampled source views; exact measured error is in reference/ui-parity-20261103/render-pose-implementation.json. This is a point/matrix algebra proof over the sampled range, not a whole-world precision bound or GPU observation. The prior player/session adapter and 720-frame, 25,739-draw full-roster simulation tests remain passing.

No assets, models, mesh/material/texture buffers, GPU uploads, draw/object counts or resource caps were added. The conversion uses fixed stack matrices and the existing 152-byte player pose cache. All 449 copied assets and predecessor executable/core hashes verify. Only win_app changed; source/docs/techplan identities and fresh test logs are recorded. Source model-group muzzle bindings remain unfitted: CAR_MODELS muzzle coordinates already specify their own attachment point.
