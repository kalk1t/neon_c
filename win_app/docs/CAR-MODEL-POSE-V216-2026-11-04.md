# Current C car model pose history - 2026-11-04

Current source/package remains v0.2.16. New RRCarPose computes the browser root/model group matrix in native shared C, including YXZ orientation, smoothstep barrel roll and stun wobble, body hover bob and nitro/kick lift. Root/model groups are unit scale; sculpted child fit/scale and pod articulation remain separate. This replaces supplied source matrix values in a new combined test, without pretending the actual raylib renderer now uses the pose.

Pose history is explicit. rr_car_pose_after_step samples speed BEFORE flight for sf=min(1,abs(speed)/135), then uses post-step time/nitro/kick for local bob=sin(t*2.3)*0.12*(1-sf*0.7) and lift=nitro*0.03+kick^2*0.07. Root bank is roll + smoothstep spin + sin(t*26)*stun*0.5. Source Car.place/sync refresh root and preserve local bob/lift. Idle changes only local bob (full 0.12 amplitude) and zeros lift after caller advances time; it does not resync root or decay flight timers. Contacts, damage and dodge can change numeric car state without changing pose until a source sync point. Pure matrix reads deliberately accept no current car pointer, preventing an accidental late recompute.

The current pack tracks poses 1..10. Countdown stores pre-flight speed and records current idle-flight pose. Playing records current rival flight/rules/recovery at the correct point: a live car can compute local pose from post-flight preserved time/nitro/kick even if rules subsequently place it; a wreck awaiting recovery keeps its old pose; an expiring wreck's place syncs root only. Reset refreshes root but keeps local history. Contacts and arsenal do not resync. Player pose 0 belongs to the player/session owner and must be advanced at its own update/place/idle boundaries. No player/session host or renderer behavior was silently changed.
