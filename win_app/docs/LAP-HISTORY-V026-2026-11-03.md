# v0.2.6 chronological lap-history HUD, 2026-11-03

## Functional correction

The browser HUD.laps renders every recorded lap in chronological order and highlights the first tied best. Its CSS uses an expanding laps-panel, not a latest-three window or a scrolling list. Windows previously displayed only the latest three entries inside a fixed146px panel and added a NO LAPS YET row absent from the browser. That changed the visible history after a fourth lap and did not match the source empty state.

The native HUD now starts at lap1, retains source order/numbering and grows the panel with history. Existing full session storage and first-best cache are reused. Empty history contains the label and BEST placeholder with no invented row. Panel offsets and row spacing follow source CSS plus the prepared v3 browser capture: header y10/height19, OL y35, two rows totaling36px, BEST y77/height16, total two-lap panel103px. Label/text sizes are moved to source15/16/13px values. Exact font weight, glow, baseline and best-label/value color styling remain visual follow-up; provided Orbitron700 substitutes for requested600 under the existing font selector.

The application draws only chronological rows whose tops enter the viewport, and clips panel paint height to the viewport. It keeps all lap data; it does not discard older rows, auto-scroll to new rows or introduce a scrollbar. With long history the browser also extends beyond the hidden-overflow viewport. Per-frame native iteration is bounded by viewport height rather than session duration. At existing test viewports at most64 rows can enter; current960x720 shows a smaller prefix. Later offscreen laps remain recorded even when not painted.
