# Results UI frame integration - 2026-11-04

Browser package and referenced source remain v0.2.16. Added rr_results_ui_frame in src/presentation/rr_results_ui.{h,c}, compiled with the shared C library in native and WASM builds. It converts native GetTime-style wall seconds to timer milliseconds, accepts an optional completed current-run tick, applies an ordered explicit hide, pumps due callbacks on every UI frame and invokes a synchronous drawing callback with the frozen published board and revision on every visible frame. Menu/paused/UI-only frames require no simulation tick. The sink contract is immutable and synchronous; the source pointer must not be retained across publication.

The exact caller boundary is deliberate: submit each completed finish event once; update the real run phase before pumping; queue finish, hide, pump, draw. Hiding does not cancel timers or change phase. An old callback can republish current race data after a same-frame hide if the current phase is finished. A callback consumed in a menu does not retry later. Drawing failure preserves the published board for repaint without replaying simulation or latching a timer failure. Missing visible-frame sink fails explicitly. Clock/queue/graph errors fail, and bad clocks latch the existing timer error. The caller must not infer a menu phase merely by hiding the card.

Fresh native and WASM builds each passed 115/115 CPU tests. New focused cases check wall-second deadline boundaries, frozen repaint after live-data changes, draw failure/repaint, missing sink, UI-only menu consumption, old/new race overlap, same-frame hide/publication, invalid graph, backwards and nonfinite clocks.
