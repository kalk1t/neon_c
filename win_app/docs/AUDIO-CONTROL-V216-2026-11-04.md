# Continuous audio target controls - 2026-11-04

Added rr_audio_current.c/h, a shared C model of the current browser's continuous engine/wind and master-volume automation commands. Each ready engine call emits three oscillator-frequency targets, engine low-pass/gain and wind low-pass/gain, in source order with exact audio-clock timestamp and setTargetAtTime constants. Master volume emits the source 0.28 multiplier with 0.03s target constant or zero when muted. This is a parameter-command port, not a sample generator, software mixer or audio backend.

The frame adapter preserves the actual source main-loop inputs: max(0,forward speed)/135, boost flag, captured playing value OR current countdown phase, and player.alive from wreck<=0. Sideways HUD speed does not rev the engine; reverse clamps to zero rather than absolute speed. Above-top/nitro fractions are not clamped to 1. Inactive/dead frames still update oscillator/filter targets but set engine/wind gains to zero. The captured playing value is intentionally supplied separately: on a countdown-to-race GO frame, the earlier playing flag remains false and the current phase is no longer countdown, so that first frame has inactive gains. Deriving playing again from current phase would change source behavior.

Methods with no prepared context produce empty plans before inspecting otherwise invalid ready-only inputs, matching lazy source controls. Muted master gain does not consult an invalid volume operand, as the source ternary specifies. Supported finite inputs and derived targets are checked; failure preserves output. Audio-clock monotonicity, node readiness and scheduling live in the future host/backend, not a guessed stateless interpolation. The plan uses at most seven fixed entries, no heap or source RNG. It does not open/resume/suspend an AudioContext/device, generate noise/impulse samples, invoke voices or alter simulation.

The isolated source VM executes the actual Sound constructor/engine/applyVolume with recording parameter nodes. Oscillator multipliers are extracted from the real source array without calling init. The actual main playing declaration and engine-call expression, CAR constants and actual alive getter are used for scripted frame-policy cases. No source imports, init, tone/rumble, AudioContext constructor, DOM, audio device or network operation executes. Current source hashes identify local browser 0.2.16, not deployment. No nickname-wrap measurements were duplicated.

The reference has 192 engine cases, 48 master cases and 1280 frame cases: 1520 cases/5176 target commands.
