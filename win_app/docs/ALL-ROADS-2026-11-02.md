# Nine-road geometry port and current evidence

Current source status, 2026-11-02. This supersedes earlier current-status notes.
The visible application still initializes Skyline. All nine roads are now
available to the shared C geometry API; this is not nine playable/qualified roads
in the UI or completion of the whole road-content parity row.

## Implemented

`src/core/rr_roads.h` defines read-only road metadata and control data.
`road_catalog_data.h` captures the current browser's nine `ROADS` definitions,
including names, control points, hand-placed checkpoints/ring counts and AI/fire
factors. No tuning or gameplay redesign was introduced.

`rr_track_init_road(track,id)` initializes any of the nine roads. Invalid integer
IDs fall back to road 1, matching browser `roadById`. Existing `rr_track_init`
and raw Skyline helpers remain compatible with the original fixtures.

Track evaluation is parameterized by the road's control points: centripetal
Catmull-Rom, 200-segment arc-length mapping, 4-unit sample spacing, positions,
tangents and local/global searches. Skyline retains its hand-placed checkpoint
fractions. Roads 2-9 reproduce the browser ring search: nominal 7%-93% spacing,
rounded search ranges, bend/run-in/vertical/deviation costs, strict best-cost
selection, transforms and nearest gate samples.

`RRTrack` stores the selected definition, actual gate count and up to 32 gate
transforms/samples. Scene/HUD/rule consumers now use actual gate counts. Runtime
still calls default Skyline initialization. The legacy `RR_TRACK_GATES` macro
remains only for recorded Skyline reference compatibility.

## Fresh headless verification

`tools/capture-all-roads.mjs` imports only current browser road/Track/Three.js CPU
code, with no browser application startup, renderer or services. It generates
the catalog, fixtures and `reference/all-roads.json`. Six source/dependency inputs
are hashed before/after capture and rechecked after compilation. Package version
is 0.2.3; file hashes identify a working reference, not a verified Git/deployed or
frozen release. Older baseline/flight/race/recovery manifests are preserved.

The new test compares all **18,052 sampled position/tangent pairs**, **117 gates**,
**729 raw/arc curve cases**, **189 nearest cases**, lengths, counts and metadata.
It also checks invalid-ID fallback and completes two ordered laps through the
generated C gates on every road, coupled to the C race rules. Worst observed
absolute error: **4.55e-12**, tolerance 1e-8; no failures.

Both full applications compile in new directories and pass **7/7** CTest tests:

- `build/all-roads-native/bin/RoadstersRace.exe` (MSVC C17, app/core warnings as errors).
- `build/all-roads-web/bin/RoadstersRace.html` plus JS/WASM/data (pinned Emscripten/raylib).

The Web build retains the previously recorded upstream raylib ES3 configuration
and stb_vorbis warnings; link and headless tests pass. No Web graphics was run.
The other six existing tests were rerun in these builds: flight/track, bounded
render policy, race rules, session lifecycle, menu activation and route recovery.
These are fresh runs of existing fixtures, not new visual qualification.

Receipts are each build's `Testing/Temporary/LastTest.log`, with preserved copies
at `reference/verification-20261102/native-seven-tests.log` and
`wasm-seven-tests.log`. Earlier five/six-test receipts remain separate.
`scripts/Test-Headless.ps1` and `-Web` discover all seven isolated tests.

The authoritative all-road catalog is generated by `capture-all-roads.mjs`.
The earlier `skyline_data.h` remains preserved historical output of
`capture-first-flight.mjs`; the parameterized implementation uses the new catalog.
Do not update one fixture/content capture and silently assume all baselines moved.
