# HUD, pause and results UI slice — 2026-11-03

Extended the existing native theme into offline race UI, using current browser `hud.js`, `style.css` and `index.html` as read-only references. No graphics window or process-control retry was attempted. This is implementation plus headless qualification, not observed visual parity.

## Implemented

- HUD uses the shared Orbitron/Rajdhani renderer: speed/boost at lower left, 300px lap/timer/checkpoint panel top center, 240px circular minimap top right, lap history at upper left and the qualified spin-dodge cooldown at lower right. Desktop HUD scale follows the browser breakpoint:0.8 when width≤1180 or height≤720, otherwise1.0. Eight-corner panel fills and clipped rectangular borders follow the source recipe; no diagonal border is invented along clip cuts. Glow/gradient rasterization remains an approximation pending matched native views.
- Minimap uses the browser-normalized projection already in shared C, now across the circular panel instead of a rectangular inner inset. It draws every existing track sample in two strokes, passed/next gates, start stripe and a heading triangle. Segment clipping is CPU geometry, with no new render texture. Gate/world positions and underlying track definitions are unchanged. Source route projection and containment are checked on all nine roads. Player triangles near/outside the rim are conservatively hidden; exact partial glyph clipping at the rim remains open.
- Timer strings match the browser HUD's `fmt`, including binary-decimal rounding cases (`1.005 -> 00:01.00`, `59.995 -> 00:59.99`, `59.999 -> 00:60.00`). The last case is the browser's existing formatting behavior, preserved rather than normalized into the next minute. Speed uses source `Math.round(abs(speed)*3.6)` semantics over the native display domain. Lap count clamps to2 for two-lap trials and remains open-ended for time attack; checkpoint text uses passed count. Completed lap display currently shows the latest3 entries with session-best time. It retains the first tied best via an O(1) append-event cache rather than scanning history each frame. Full scrollable time-attack history is still a parity gap.
- Countdown/finish/warnings/checkpoint messages and projected heading/target markers use the shared fonts and source placement/style cues. Target marker is a pulsing green diamond. Existing race/recovery events and session clocks remain authoritative; no second simulation step or new gameplay rule was introduced.
- Pause is a centered380px card with Resume/Restart/Main Menu and truthful native instructions. Restart routes through existing `start_flight` session/world initialization. Resume preserves the prior countdown/active/finish/results phase; focus and overload safety behavior remains. Buttons now require the application to be focused before accepting a click. Browser drag/zoom showcase interaction is not implemented, so its hint was not falsely displayed.
- Results uses the source680px centered card, FINISH/title hierarchy, formatted total, first-best highlighted laps, two-column standings/coin structure and themed restart/menu controls. Offline rows explicitly say solo/no rivals/no rewards/account not connected. No fake placements, wallet balance, unlock, next-road grant or online save is shown. The existing error state retains return-to-menu behavior.
