# Shared-C cue submission integration, 2026-11-04

rr_audio_submit.c/h connects the existing raw cue recipes and voice dispatcher into a reusable, source-ordered submission function. It replaces manual caller/test composition with explicit RNG, per-helper clock and partial-failure handling. Main is unchanged and production audio remains inactive; no graph nodes, samples, audio context/device or thread are created.

Blaster jitter is drawn before context/voice guards, even when nothing can play. Rumble offset RNG stays dispatcher-owned and admitted-only. Each admitted helper reads the caller's audio-context clock separately; skipped helpers do not read or require it. Readiness represents an existing warmed context/graph; source helpers inspect context presence rather than playback or simulation phase. Master mute/volume are not added as admission guards. Original request indices and all reserved voice tokens remain visible. Callers supply a valid single-owner bank and non-reentrant RNG/clock callbacks; the clock is independent of simulation race time.

Invalid pointers/enum/bank fail before work and preserve output. Once work starts, any failure publishes consumed RNG/clock counts, the processed prefix, failed request and every reserved token, with complete=false. Missing/invalid provider and invalid clock tests retain the successful prefix without replay or fictional RNG rollback. The caller must retire returned tokens and stop/recover explicitly. This is a documented C failure policy, not qualification of invalid WebAudio exceptions. Existing voice lifetime rules and callbacks remain authoritative.

The previous original-Sound oracle is reused:216 actual source cases,253 voice commands,73 source RNG observations and18 advancing-clock fixtures from local browser v0.2.16. New tests call rr_audio_submit_cue directly for all18 cues, with no hand-composed recipe jitter or dispatch loop. They compare exact schedule/gain/filter/pan/offset commands, observe RNG before/after voice reservations, count admitted-only clock reads and verify ended delivery. Existing recipe/dispatch implementations and oracle files are byte-identical; source audio/package hashes still match. No new browser/audio capture or deployment check was made.

Exact new integration check counts, command error and submission-result struct sizes are in the receipt; internal fixed temporary buffers also exist and peak stack usage was not measured. Additional boundaries cover no-context/full-cap blaster draws, absent clock/RNG providers, invalid jitter, a clock failure after a successful tone, a rumble RNG failure after prior reservations, malformed bank/enum preservation and unused-parameter acceptance. No heap/sample/GPU allocation or resource-cap change was added. Main, predecessor and455 copied assets were verified before launcher promotion. The latest client has no new audible or UI behavior from this independent integration.
