# Roadster cockpit candidate — 2026-11-03

Implemented an opt-in native cockpit candidate using the existing browser art and current `cockpit.js`/camera behavior. `RR_COCKPIT_PREVIEW` is **OFF by default**. Graphics/process verification is still unresolved, so this is not a qualified production feature. No game window was launched.

## Concrete implementation

- Added `rr_cockpit_plan.h`: all three browser car layouts, normalized control/panel boxes, pivots, per-panel scale factors,1672×941 cover fit,20% bottom drop, readout formatting, quantized steering and visibility rules. Source formulas and data are preserved; no new dashboard design was generated.
- Added `rr_cockpit.{h,c}`: Roadster illustrated base, native speed/boost/lap/time/pulse-status readouts and steering yoke rotation around the source pivot. Layer order is base→readouts/icons→controls→regular HUD. Cockpit uses its own floor-to-centiseconds timer, matching source `cockpit.js`, rather than the separately rounded HUD timer. The pulse area says NOT CONNECTED in the current offline host; no combat readiness, heat, wallet or progress is invented. The pure readout component also supports source heat/overheat states for later qualified binding.
- In the **candidate configuration only**, I toggles cockpit during countdown/active/finished, C exits it before changing chase modes, and right-button free look hides the dashboard until the source orbit threshold is met again. Preference is session-only; no local settings/account persistence was introduced. The native host still has its original two chase modes; the browser's separate third raw first-person mode is not part of this slice.
- Candidate seat follows `car.pos + car.fwd*.6 + (0,1.5,0)`, looks down0.2 radians and adds8 to the smoothed FOV target. Body mesh is hidden while inside; existing thruster effects remain through `rr_scene_car_view`. HUD speed/lap panels hide only when the ready cockpit is visible, while minimap/history/spin and warnings remain layered above it. Pause/results/menu hide cockpit art; phase/resume/restart behavior remains in the shared session controller.
- Cold resource preparation is restricted to focused menu/pause frames without a pending world load. At most one cockpit image is decoded/uploaded per such frame, then CPU image memory is released. City/world rendering and uploads do not run in those phases. An incomplete/failed pack retains the exterior/HUD path. Dimensions are checked before upload, partial loads are cleaned up on failure, and textures unload on shutdown. Default builds do not request or upload cockpit textures.

Separate `build/cockpit-default-native`/`cockpit-default-web` compile/package checks explicitly set the optionOFF and testsOFF; they are build-only evidence, not extra passed tests. Headless source-equivalence coverage includes18 fit cases (six viewports × three layouts),36 source readout/control states, all99 layout scalars and18 source Three.js seat poses. Tests cover empty/partial/full boost, rounding, finite/infinite/free-roam lap labels, heat threshold/overheat, steering quantization/easing, phase/ready/free-look visibility and seat/FOV offset. PNG tests use raylib CPU decoding, verify dimensions, transparent/nonempty alpha and resource totals without initializing a window/GPU. The fixture capture tool executes actual source fit/update methods against simple DOM string/style stubs plus Three math, without auth, browser, graphics or storage operations.

The first fixture incorrectly kept a numeric speed as a C string pointer: native headless test failed and WASM compilation rejected it. The DOM stub now coerces `textContent` exactly as a browser does, and the pure cockpit test compiles with warnings as errors. Invalid fixtures and failure logs are preserved. A later native assertion exactly at the0.05 orbit threshold exposed a last-bit math-library difference versus WASM; the browser's formula remains unchanged, and portable tests now check just inside/outside. Exactly-on-threshold cross-platform visibility may differ by one floating-point rounding step; no epsilon or alternate gameplay rule was introduced. All failures are distinct from final successful checks and from unrun graphics.
